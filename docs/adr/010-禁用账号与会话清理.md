# ADR-010：禁用账号与会话清理

## 状态

已接受（Sprint 4 · T4-02，实现见 PR #127；验证记录见 `docs/reports/s4-disable-account.md`，随 PR #127 合入）。

## 背景

CampusOverflow 使用 Redis 服务端会话（ADR-003），登录成功后浏览器持有 `SESSION` Cookie。
如果管理员只是把 `id_user.status` 改成 `DISABLED`，该用户已有的会话仍然有效：
旧 Cookie 还能继续访问接口，直到 30 分钟会话超时。这不符合“禁用后立即失效”的安全预期。

管理员禁用账号时必须同时满足：

1. 账号状态变为 `DISABLED`，之后不能再次登录；
2. 该用户已经登录的所有浏览器/标签页立即失效；
3. 不能误踢管理员自己的会话；
4. 操作留下审计记录。

## 决策

1. **领域层**：`User.disable(Actor)` 只允许 ADMIN；管理员不能禁用自己（`BusinessRuleException` ID-1007）；
   状态置为 `UserStatus.DISABLED`，`canLogin()` 返回 `false`。
2. **应用层**：`AdminUserService.disable` 在同一个事务中完成：
   - 加载用户并执行 `user.disable(actor)`；
   - 保存用户；
   - 调用 `UserSessionRevoker.revokeAll(user.username())`；
   - 写审计 `DISABLE_USER`。
3. **端口/适配器**：应用层只依赖 `UserSessionRevoker` 端口；
   `SpringSessionUserSessionRevoker` 用 Spring Session 的
   `FindByIndexNameSessionRepository.findByPrincipalName(username)` 找到该用户名下全部会话并逐个删除。
4. **会话索引**：`spring.session.redis.repository-type=indexed`；登录成功时 `AuthController`
   把用户名写入 `FindByIndexNameSessionRepository.PRINCIPAL_NAME_INDEX_NAME` 索引，
   否则无法按 principal name 找到会话。
5. **接口**：`PUT /api/v1/admin/users/{userId}/disable`，成功返回 `204 No Content`；
   URL 级授权仍由 `SecurityConfig` 的 `hasRole("ADMIN")` 兜底。

## 后果

正面：

- 禁用后旧 Cookie 访问 `/api/v1/auth/me` 直接 401，不需要等会话超时；
- 重新登录被拒绝（账号 `DISABLED`，`canLogin=false`）；
- 管理员自己的会话不受影响；
- 所有设备/标签页同时失效，审计可追溯。

代价与约束：

- 依赖 Redis 和 Spring Session 的 indexed 仓库；Redis 不可用时无法撤销会话；
- 会话索引会额外占用少量 Redis 内存；
- 禁用是全局操作，不能只踢某一个设备；
- 账号禁用没有反向“启用”接口；如后续需要，必须同时设计恢复登录与会话策略。

## 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 改用 JWT，并在 Redis 维护黑名单 | 与 ADR-003 的服务端会话决策冲突；要额外处理黑名单过期、时钟和分布式一致性 |
| 只改账号状态，等会话自然过期 | 最长 30 分钟内旧会话仍可访问，不满足“立即失效” |
| 删除 Redis 中所有 `co:session:*` | 会误踢全部用户，影响面不可接受 |
| 扫描 Redis key 按前缀匹配用户名 | 依赖 key 结构，O(N) 且容易误删；应使用 Spring Session 的 principal-name 索引 |
| 每个请求查数据库确认账号状态 | 增加数据库压力；可在登录和关键操作校验，但不能替代会话撤销 |

## 验证

- `AdminUserServiceTest` 3/3：
  1. 非 ADMIN 禁用 → `ForbiddenException`；
  2. 管理员禁自己 → `BusinessRuleException` ID-1007；
  3. 禁用他人 → 状态 `DISABLED`、会话被撤销、审计 `DISABLE_USER`、`canLogin=false`。
- 真实链路（PR #127 验证记录）：禁用后旧 Cookie 访问 `/api/v1/auth/me` → `401 AUTH-401`；
  被禁用账号重新登录 → `401`；管理员本人仍为 `200`。
- 复现命令：

```bash
mvn -f backend/pom.xml -pl co-identity/co-identity-application -am test -Djacoco.skip=true
```
