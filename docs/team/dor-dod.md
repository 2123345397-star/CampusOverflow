# DoR / DoD（就绪定义 / 完成定义）

> 团队：TeamX　项目：CampusOverflow　版本：v1.0
> 所有条目必须可判定：满足或不满足都能通过客观证据确认，不使用“基本完成”“差不多”等模糊表述。

## 一、DoR（Definition of Ready，任务可以开始的条件）

一个任务进入 In Progress 前，必须同时满足：

1. 看板卡片存在，标题、唯一编号、负责人齐全，且只有一个负责人。
2. 验收标准明确：用户故事至少包含可核对的 Gherkin 场景（Given/When/Then）或等价清单。
3. 依赖已确认：所依赖的接口、设计或他人任务已明确，无未解决的阻塞项。
4. 工作量已估算（Story Points 或工时），且在当前 Sprint 容量内。
5. 相关术语与 `docs/ddd/glossary.md` 一致，无歧义名词。

判定方式：以上 5 条全部能在卡片/仓库中核对为“是”，任务才允许从 To Do 移入 In Progress。

## 二、DoD（Definition of Done，任务算完成的条件）

一个任务移入 Done 前，必须同时满足：

1. 代码已提交并推送到功能分支，且通过编译与全部单元测试（mvn test / npm run build 为绿色）。
2. 至少 1 名有写权限的成员完成代码评审并 Approve（评论 LGTM），评审意见已全部解决。
3. 验收标准逐条核对通过：对应 Gherkin 场景全部通过，无遗留 P0/P1 缺陷。
4. 相关文档已同步更新（接口、错误码、架构或术语变更时）。
5. PR 已合并到目标分支、功能分支已删除，看板卡片已移入 Done。
6. 无明文密钥、无调试残留（console.log、注释掉的代码块等）。

判定方式：以上 6 条全部有客观证据（CI 结果、评审记录、场景运行结果、合并记录），缺一不可，否则不允许宣称“完成”。
